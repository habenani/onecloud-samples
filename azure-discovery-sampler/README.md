# Azure discovery sampler

One small deployment with one of each Azure resource type OneCloudify records in the CMDB. Use it to check how your instance records each type after an apply: written from the Terraform state, confirmed by targeted pattern discovery where the resource type map names a pattern, or kept in the generic Cloud Resource class when the type has no mapping. Order it, read the CMDB and Discovery steps on the run, then Remove it.

What it creates (UK South by default): resource group, virtual network and subnet, network security group (SSH from one CIDR block) on the subnet, two Standard static public IPs, network interface, a Linux virtual machine (Ubuntu 22.04, `Standard_B2ats_v2`) with a 4 GB data disk, a user assigned managed identity (a type with no mapping, so it is recorded in the generic class), a one node AKS cluster (Free tier, `Standard_D2as_v4`), a container group with one small container, an Azure SQL server with one Basic database (password generated by Terraform, kept only in the state) and a Standard load balancer with a public frontend and one backend pool that holds the virtual machine.

Cost: the AKS node, the virtual machine, the load balancer and the database are billed by the hour. A check takes about 30 to 45 minutes from order to Remove; do not keep it longer.

## What the requester fills in

| Variable | Notes |
|---|---|
| `name` | Base name, 2 to 20 lowercase characters |
| `new_resource_group_name` | Name of the new resource group the sampler creates; Remove deletes it |
| `ssh_public_key` | One OpenSSH public key line |
| `ssh_source_cidr` | Who may reach the VM on port 22 (default a documentation range, so nobody) |
| `vm_size`, `aks_node_size` | Smallest sizes your subscription offers; check `az vm list-skus --location <region>` |
| `location`, `tags`, `test_tag` | Filled by OneCloudify or left empty |

## What to check after the order

Open the run and the deployment's resources: every Azure resource has a row, mapped types have a CI of their class, types with a pattern show a Discovery status, the user assigned identity sits in Cloud Resource (`cmdb_ci_cmp_resource`) and the association resources have no CI (they are links, not resources). The OneCloudify guide Cloud accounts and Discovery, section 9.6, lists the expected result per type.

## Provider version

`hashicorp/azurerm` 4.x and `hashicorp/random` 3.x. The provider reads `ARM_SUBSCRIPTION_ID` from the environment, which OneCloudify exports from the cloud account.
